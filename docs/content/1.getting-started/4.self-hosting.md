title: Self-Hosting
description: Run PimaBill on your own servers with Docker, and what differs from the hosted cloud.
---

PimaBill is open source (AGPL-3.0). You can run the whole platform yourself, with no limits on organisations, customers or invoices. Everything below is free.

## What you need

- A Linux server with Docker and Docker Compose (2 GB of memory is enough to start)
- A domain for the API and one for the dashboard, behind a reverse proxy with TLS
- SMTP credentials for emails (invoices, password resets, invitations)
- Your own account with at least one payment provider (Flutterwave, Paystack, Stripe, MTN MoMo, Airtel Money, Yo! Payments, PayPal and more)

## Install

```bash
curl -O https://raw.githubusercontent.com/pimabill/billing/main/docker-compose.prod.yml
curl -O https://raw.githubusercontent.com/pimabill/billing/main/.env.example
cp .env.example .env
```

Fill in `.env`. These are required:

| Setting | What it is |
|---|---|
| `CENTRAL_DB_PASSWORD`, `TENANT_DB_PASSWORD` | Database passwords (`openssl rand -hex 24`) |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | Session signing secrets, different from each other (`openssl rand -hex 32`) |
| `ENCRYPTION_KEY` | Encrypts provider credentials and database URLs (`openssl rand -hex 32`); keep a copy: without it they cannot be read |
| `API_URL`, `DASHBOARD_URL` | Your public addresses, e.g. `https://api.example.com` and `https://app.example.com` |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASSWORD`, `EMAIL_FROM` | SMTP |

Then start it:

```bash
docker compose -f docker-compose.prod.yml up -d
```

The API listens on port 4000 and the dashboard on 4002 (change them with `API_PORT` and `DASHBOARD_PORT`). Put both behind your reverse proxy; `nginx.conf.example` in the repository is a starting point. Database migrations run on start, and each organisation gets its own database when it signs up.

## Updating

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

Back up the two PostgreSQL volumes and your `.env` before updating. Releases and what changed are on the GitHub releases page.

## Branding

`BRAND_NAME`, `BRAND_LOGO`, `BRAND_TAGLINE`, `BRAND_PRIMARY` and `BRAND_SUPPORT_EMAIL` put your own name on emails, invoices and the API reference.

## A sandbox

Run a second deployment with `SANDBOX_MODE=true` for testing with providers' test accounts, and give your live dashboard a switch to it. See [Sandbox](/guides/sandbox).

## What is different from the cloud

| | Self-hosted | Cloud |
|---|---|---|
| Price | Free | Free up to 1,000 customers; Growth, with no limits, about $10 a month in your currency (UGX 35,000, KES 1,250, NGN 15,000, …) |
| Limits | None | Per plan; see [Plan limits and access](/guides/plan-limits-and-access) |
| Payment providers | Your own accounts | Your own accounts, plus managed payments |
| **Managed payments** | **Not available** | Included: take payments through the platform's provider accounts |
| Servers, updates, backups | Yours | Ours |

Managed payments are a service run by the cloud: the platform's own provider accounts collect for you and pay you out, with review and payouts handled by the platform. A self-hosted deployment always uses its own provider accounts. Connect them in **Settings → Payment providers**.
