PimaBill is open source (AGPL-3.0). You can run the whole platform yourself, with no limits on organisations, customers or invoices. Everything below is free.

## What you need

- A Linux server with Docker (2 GB of memory is enough to start)
- For a public install, two domains pointed at the server, with ports 80 and 443 open
- SMTP credentials for emails (invoices, password resets, invitations); you can add these later
- Your own account with at least one payment provider (Flutterwave, Paystack, Stripe, MTN MoMo, Airtel Money, Yo! Payments, PayPal and more)

## Install

Run this in the folder where you want PimaBill to keep its settings:

```bash
docker run -it --rm \
  --volume /var/run/docker.sock:/var/run/docker.sock \
  --volume "$(pwd)"/pimabill:/install \
  ghcr.io/pimabill/installer:stable
```

The installer asks for your domains and SMTP details, generates every password and secret, starts PimaBill and waits until it is ready. With domains, it gets HTTPS certificates for you. Leave the domain empty to try PimaBill on your own computer at `http://localhost:4002`.

It writes `docker-compose.yml` and `.env` into the `pimabill` folder. Keep a copy of `.env` somewhere safe: without `ENCRYPTION_KEY`, stored provider credentials cannot be read.

### Install without prompts

For automated installs, pass the answers with `--env`, and leave out `-it`:

| Setting | What it is |
|---|---|
| `PIMABILL_DASHBOARD_DOMAIN`, `PIMABILL_API_DOMAIN` | Your domains |
| `PIMABILL_TLS_EMAIL` | Email for certificate notices |
| `PIMABILL_EMAIL_HOST`, `PIMABILL_EMAIL_PORT`, `PIMABILL_EMAIL_USER`, `PIMABILL_EMAIL_PASSWORD`, `PIMABILL_EMAIL_FROM` | SMTP |
| `PIMABILL_API_PORT`, `PIMABILL_DASHBOARD_PORT` | Local ports, 4000 and 4002 by default |

### Use your own reverse proxy

Leave the domain empty, then change `DASHBOARD_URL` and `API_URL` in `.env` to your public addresses. The API and dashboard listen on `127.0.0.1` only. `nginx.conf.example` in the repository is a starting point. The dashboard needs HTTPS outside `localhost`, because sign-in cookies are secure.

## Updating

Run the same command with `upgrade` at the end, from the same folder:

```bash
docker run -it --rm \
  --volume /var/run/docker.sock:/var/run/docker.sock \
  --volume "$(pwd)"/pimabill:/install \
  ghcr.io/pimabill/installer:stable upgrade
```

It backs up both databases and your settings to `pimabill/backups`, moves to the newest release and waits until it is ready. Releases and what changed are on the GitHub releases page.

If install or upgrade fails with `client version is too new`, add `--env DOCKER_API_VERSION=1.42` with your server's version.

## Branding

`BRAND_NAME`, `BRAND_LOGO`, `BRAND_TAGLINE`, `BRAND_PRIMARY` and `BRAND_SUPPORT_EMAIL` put your own name on emails, invoices and the API reference.

## Bot protection

To put Cloudflare Turnstile on sign-in, sign-up and password reset:

1. Create a widget at **dash.cloudflare.com → Turnstile** and add your dashboard's hostname.
2. Set `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` in `.env`.
3. Restart the API.

The dashboard shows the widget as soon as the API reports a site key. Leave both settings empty to turn it off.

## A sandbox

Run a second deployment with `SANDBOX_MODE=true` for testing with providers' test accounts, and give your live dashboard a switch to it. See [Sandbox](/guides/sandbox).

## What is different from the cloud

| | Self-hosted | Cloud |
|---|---|---|
| Price | Free | Free up to 500 customers; Growth, with no limits, $15 a month; Enterprise on request |
| Limits | None | Per plan; see [Plan limits and access](/guides/plan-limits-and-access) |
| Payment providers | Your own accounts | Your own accounts |
| Servers, updates, backups | Yours | Ours |

Connect your provider accounts in **Settings → Payment providers**.
